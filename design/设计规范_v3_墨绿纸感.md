# 离线 AI 聊天工具 · 界面方案 v3（墨绿纸感）

> 交付物：`design/mockup-v3.html`（高保真可交互原型，离线单文件）
> 目标：在保留现有全部功能的前提下，让非技术用户「打开就会用」，同时让界面有明确的性格，不像通用 AI 产品。

---

## 一、设计上下文

| 项 | 结论 |
|---|---|
| 受众 | 作者本人 + 拿到压缩包的老师/同学；非技术背景，多为 14–16 寸 Windows 笔记本，键鼠为主，偶尔触控板 |
| 核心任务 | ① 直接提问 ② 把文档/图片丢进来问 ③ 找历史会话 ④ 换模型/看状态 |
| 关键约束 | 纯离线（不能依赖网络字体/CDN）、16GB 内存（需暴露内存状态）、单手可用键盘完成主流程 |
| 气质 | 安静、可信、纸感；不要「AI 蓝紫渐变 + 发光」那套 |
| 记忆点 | **左侧一道墨绿细线**（会话列表最左、AI 回答最左）+ 宋体标题，像在笔记本上批注 |

**对比度实测**（WCAG AA 需 4.5:1）

| 组合 | 比值 | 判定 |
|---|---|---|
| `--ink` on `--paper` | **15.0 : 1** | AAA |
| `--muted` on `--paper` | **5.3 : 1** | AA |
| 白字 on `--moss`（发送按钮） | **7.8 : 1** | AAA |
| `--seal` on `--seal-tint` | **5.6 : 1** | AA |

### 字体

| 角色 | 字体栈 | 字号/行高 | 用途 |
|---|---|---|---|
| 展示 | Noto Serif SC → Source Han Serif → Songti | 26 / 1.35 | 空状态标题、品牌字 |
| 正文 | HarmonyOS Sans SC → PingFang SC → Microsoft YaHei | 14 / 1.78（回答）、13.5 / 1.7（用户） | 对话 |
| UI | 同上 | 13 / 1.6 | 按钮、列表 |
| 辅助 | 同上 | 11.5 / 1.5 | 时间、提示、上下文计数 |
| 等宽 | JetBrains Mono → Consolas | 12.5 | 模型名、代码 |

**为什么用宋体做标题**：整屏只有标题用衬线，形成"抬头—正文"的节奏，也是廉价但有效的性格来源（全部无衬线就回到通用 AI 脸）。

### 间距 / 圆角 / 阴影

- 间距基数 **4px**，实用档位：`4 / 8 / 12 / 16 / 24 / 32`
- 圆角：控件 `8`，卡片/浮层 `12`，输入框与用户气泡 `18`（气泡右下角 `4` 形成方向感）
- 阴影：`shadow-1` 静态卡片；`shadow-2` 悬浮/浮层（暖色阴影，不用纯黑）
- 动效：`cubic-bezier(.22,1,.36,1)`，时长 `140–180ms`；`prefers-reduced-motion` 下全关

## 三、布局

```
┌──────────────┬──────────────────────────────────────────────┐
│ 侧栏 264px   │ 顶栏 56px   标题 / 模型 chip / 导出 / 更多    │
│ 品牌         ├──────────────────────────────────────────────┤
│ 新建对话     │ 消息流（列宽 max 720，左右留白 ≥32）           │
│ 搜索         │   日期分隔线                                  │
│ 会话分组     │   用户：右对齐气泡（≤78% 宽）                  │
│  今天/昨天   │   AI：左对齐，左侧 2px 墨绿线，无气泡           │
│              │   备注/错误：左对齐内联卡片（max 560）          │
│ 记忆 / 设置  │                                              │
│ 状态         ├──────────────────────────────────────────────┤
└──────────────┴──────────────────────────────────────────────┤
               │ 输入卡（max 720）：附件 chips → 文本域 → 工具行 │
               │ 提示行：Enter 发送 · 上下文 1.2k/6k             │
               └──────────────────────────────────────────────┘
```

- 窗口默认 **1080×720**，最小 **900×620**
- 宽度 `< 960px`：侧栏收为 **64px 图标栏**（hover 展开），保证对话列不小于 520
- 对话列永远居中且 `max-width: 720`；超过 1200px 不再拉宽（长行难读）

## 四、组件规范与状态

### 1. 会话项（侧栏）

| 状态 | 表现 |
|---|---|
| 默认 | 透明底，标题 13.5/500，副行 11.5 `--muted-2`（时间 · 模型/文档数） |
| hover | 背景 `surface` 60% |
| 当前 | 背景 `surface` + `shadow-1` + **左侧 2×高度-20 的墨绿竖条** |
| 长标题 | 单行省略，不换行（列表节奏优先） |

### 2. 消息

- **用户**：右对齐气泡，`--moss-tint` 底 + 14% 主色描边，`18/18/4/18` 圆角
- **AI**：无气泡。`border-left: 2px solid var(--moss)` + 左内边距 16，行高 1.78
  - 头部元信息：模型名 · 耗时 · token 数（11.5 `--muted-2`）
  - 悬停才出现操作条（复制 / 朗读 / 重试），避免常驻噪音；`focus-within` 也显示（键盘可达）
  - 引用卡片：`[1]` + 文件名 + 页码，11.5 等宽页码
- **系统/错误**：**左对齐内联卡片**（max 560），不再用居中窄条
  - 这直接修掉了旧版"提示条被折成一条竖列"的问题
  - 三档：默认（信息）/ warn（内存、参数）/ err（模型异常），各配语义色与图标

### 3. 输入区

- 卡片形态，focus 时 3px 主色光晕（不是变色边框硬跳）
- 附件 chips 在文本域上方，`×` 命中区 16×16（视觉小、可点区够）
- 工具行：`文档 / 语音 / 深度` 为**可切换 pill**，按下态用 `moss-tint` + 内描边；录音态切 `seal`
- 发送：34×30 实心主色，hover 上浮 1px（唯一有位移的按钮，强化主操作）
- 提示行常驻：左「Enter 发送 · Shift+Enter 换行」，右「上下文 1.2k / 6k + 细进度条」
  - 上下文条用 3px 细线而非环形仪表，和不打扰的基调一致

### 4. 模型选择

- 顶栏 chip（等宽字体显示模型名）→ 点击弹出 268px 浮层
- 每项：模型名（等宽）+ 体积（右对齐）+ 选中勾
- 浮层底部一句提示："切换会自动释放上一个模型" —— 把上一版的内存坑变成设计里的信任点

### 5. 空状态

- 宋体 26px 标题「问点什么，或者把文件丢进来。」
- 三张起步卡：读文档 / 解释报错 / 起草文字，hover 上浮 2px
- 副文案说明支持格式，替代"帮助文档"

### 6. 状态

| 状态 | 表现 |
|---|---|
| 思考中 | 7px 主色圆点 1.5s 呼吸 + 文案「正在思考草稿…」，不用转圈 spinner |
| 录音中 | 语音 pill 变 `seal` 底 + 文案「录音中…」 |
| 错误 | 内联 err 卡片，标题加粗说明发生了什么 + 编号列出处理步骤 |
| 禁用 | 透明度 60%，`cursor: not-allowed` |

## 五、可访问性

- 全键盘可达：`Tab` 顺序 = 侧栏 → 顶栏 → 消息操作 → 输入 → 工具 → 发送
- 焦点环统一 `2px solid --moss` + `2px offset`（夜读模式下自动切浅绿）
- 图标按钮全部有 `aria-label`；工具 pill 用 `aria-pressed`；模型浮层 `aria-expanded/haspopup`
- 触控目标 ≥ 32×32（桌面）+ ≥ 44×44（触屏模式可加 `@media (pointer: coarse)`）
- 对比度见上表，正文全部 AA+
- `prefers-reduced-motion` 下关闭动画与平滑滚动
- 错误文案不写"出错了"，写"发生了什么 + 三步怎么办"

## 六、落到 PySide6（实施说明）

QSS 不支持 `color-mix`/CSS 变量，需要预计算后写死或用占位替换。

| 设计 | Qt 实现 |
|---|---|
| 令牌 | 新增 `chatui/theme.py`：`TOKENS = {"paper": {...}, "night": {...}}`，`qss(theme)->str` 用 `{paper}` 占位 `.format()` |
| 侧栏 | `QListWidget`（`setItemWidget` 自定义行）或 `QVBoxLayout` + 自绘 `SessionRow`；选中态用 `QSS ::item:selected` + 左侧 2px `border-left` |
| 搜索 | `QLineEdit` + `addAction(icon, LeadingPosition)` |
| 顶栏 | 固定 56px `QHBoxLayout`；模型 chip 用 `QPushButton` + 自定义 `QMenu`（`setStyleSheet` 圆角、项高 34） |
| 消息 | 沿用现有 `BubbleItem`，改三处：① AI 角色改为 `border-left` 容器（QFrame + QSS）② 用户气泡圆角改 `18/18/4/18` ③ 系统/错误改用 `NoteCard`（QFrame + 图标 + 富文本），替换原居中 chip |
| 输入卡 | `QFrame#composer` + `QPlainTextEdit`（`setVerticalScrollBarPolicy` 自适应高度）+ 工具行 `QToolButton`（`setCheckable(True)`） |
| 阴影 | `QGraphicsDropShadowEffect`（模糊 20，偏移 0/6，色 `rgba(23,33,29,40)`），只给浮层与输入卡，避免性能损耗 |
| 字体 | `QFontDatabase` 探测 `Noto Serif SC / Source Han Serif SC / SimSun`，标题 fallback 到宋体；正文 `Microsoft YaHei UI` |
| 主题切换 | `QApplication.setStyleSheet(qss(theme))`，立即生效，无需重启 |

**改动范围**：`chatui/chat_app.py`（布局与组件样式）、新增 `chatui/theme.py`；数据与交互逻辑不动（会话/文档/语音/深度思考照旧）。

**风险与对策**

1. QSS 对 `border-radius` + `background` 组合的渲染在部分控件上不一致 → 统一用 `QFrame` 容器包一层，避免直接给 `QWidget` 设背景。
2. 自绘 hover 操作条需要 `enterEvent/leaveEvent` → 用 `QWidget.eventFilter` 包一层，避免每个气泡装定时器。
3. 侧栏 264px + 对话 720px = 984px，最小窗口 900 会挤 → 已定 `<960` 收成 64px 图标栏。

### 落地时踩到并修掉的 4 个坑

1. **欢迎卡残留压住对话**：`removeWidget` 后 widget 仍挂在父级上，`deleteLater` 前会按旧几何继续绘制 → 补 `hide() + setParent(None)`。
2. **中文不换行被裁切**：只设气泡宽度不够，Qt 把无空格中文当成一个不可断的"词"，`minimumSizeHint` 撑破布局 → 同时 `label.setFixedWidth()`，强制按目标宽度折行。
3. **AI 正文缩成窄条**：QLabel 的 rich-text `sizeHint` 很小 → AI 气泡固定为阅读宽度（`min(feed*0.74, 720)`）。
4. **夜读下图标几乎不可见 / 发送键白图标对比度不足**：图标是 QIcon 位图，QSS 管不到颜色 → 用令牌重绘（深色底用 `muted`，实心按钮用 `send_fg`）。

| 模型菜单 | 顶部说明 + 当前项打勾图标 + 底部容量提示 | 仍是原生 QMenu（自定义浮层留待需要时再做） |

### 这批踩到的 3 个 Qt 布局坑（都已修）

1. **中文富文本“高度算不准”**：`QLabel.heightForWidth()` 对富文本直接返回单行高度（实测 27px），导致只显示一行/最后一行被操作条压住。
   → 用 `QTextDocument.setTextWidth()` 排版后取真实高度，再 `setFixedHeight(height*1.02+8)` 留余量。
2. **消息项被 feed 拉伸**：`BubbleItem` 竖直策略是 Preferred，feed 把多出来的高度平均分给每条消息，表现为消息之间出现巨大空洞、操作条跑到正文中间。
   → `setSizePolicy(Preferred, Fixed)`，高度完全由内容决定。
3. **输入卡要么缩成一小条、要么被拉得很高**：`AlignHCenter` 只取 sizeHint；`Expanding` 又会让 QTextEdit 撑满。
   → 用 `addStretch(1) + addWidget(card, 10) + addStretch(1)` 居中并控制宽度，卡片 `SizePolicy(Expanding, Maximum)`，输入框初始 `setFixedHeight(56)` 后交给 `_autosize()`。

### 测试适配

消息容器从 `feed.v` 改为 `msg_layout`，相关断言同步更新（3 处遍历 + 1 处计数断言已核对）。

## 十、第三批落地记录（2026-10-18 · 已实现）

| 项 | 实现 | 关键点 |
|---|---|---|
| 阅读列真·max-width | `QScrollArea.setMaximumWidth(760)` + 居中行 | 滚动条贴在内容右侧，不再贴窗口边缘；窗口极宽时行宽稳定 |

### 审查时一并修掉的 4 处

1. **引用色写死深绿** → 夜读下几乎看不见：改为按主题取 `moss`。
2. **`_model_sizes()` 超时 2s** 会让点击模型按钮时界面冻结：缩到 0.8s（失败就只显示名字）。
3. **清空/切换会话后引用来源仍指向上一份文档**：两处都清空 `_cite_sources`。
4. **搜索过滤后空分组标题仍显示**：过滤后回扫，整组不可见就隐藏组名。
