## 关键设计决策

1. **向量模型走 ONNX 直连，不走 Ollama**
   本机 Ollama 0.40.5 构建未开放 embeddings（CLI 也无 `--embeddings`），
   因此用 fastembed + `specific_model_path` 直指 `model_assets/embed/BAAI/bge-small-zh-v1.5`
   （94.8MB，512 维，2.5ms/条，0.3s 加载）。模型缺失时 `embed.available()` 为 False，
   检索静默退回 BM25，功能不中断。

2. **融合用加权 RRF（0.55 BM25 / 0.45 向量），不用分数加权**
   两路分数量纲不同（BM25 无上界、cos 在 [-1,1]），直接相加会互相淹没；
   只看名次的 RRF 天然免疫这个问题，权重调节也更直观。

3. **向量增量补算 + 片段 id**
   每个 chunk 带 `id = sha1(path + 文本前 200 字)`，`vectors.npy` 只补算新片段，
   删除文件时丢弃陈旧行；索引重建时按 id 复用已有向量，避免每次全量重算。

4. **`run_python` 默认关闭 + AST 静态检查**
   此前已因为"白名单校验首个词可被 `cat x && python evil.py` 绕过"而移除 shell 执行（等价 RCE）。
   新增的代码执行保留三重护栏：① 默认 `agent.allow_python: false`；
   ② AST 检查禁危险 import（os/sys/subprocess/socket/open/eval/…）与 dunder 逃逸；
   ③ 子进程 `-I` 隔离 + 超时强杀 + 全程审计。

5. **写文件 = 快照 + 审计 + 可回滚**
   `write_file` 前先把原文件快照到 `.offline-audit/snapshots/`，
   审计日志 `audit.jsonl` 只记"改变型"动作（只读动作不记，防日志爆炸），
   MCP `local_undo` / `Audit.rollback()` 一键还原；新建文件的回滚等于删除。

6. **小模型 ReAct 的三个常见坑，逐个打了补丁**
   - 照抄示例路径 → `_norm_path` 剥掉工作区同名前缀；
   - 续写整段对话（伪造 Observation）→ `_cut_hallucination` 截断幻觉；
   - 读够了却不写 → 写任务显式点名 `write_file`、重复动作当场提醒、
     直接给答案时再要一次"请把内容落盘"。

7. **深度思考的中间产物不进历史**
   草稿与自检意见只在界面上收成提示条，不写进 `history`，
   否则下一轮上下文会被前一轮的草稿+自检撑爆（num_ctx 只有 6144）。

## 语音输入故障修复（用户截图反馈，同日）

现象：点麦克风报 `语音输入失败：Error querying device -1`。

根因链（本机实测逐层剥开）：

1. `sd.default.device = (-1, 1)` —— Windows 没设默认输入设备，
   `query_devices(kind="input")` 直接抛 `PortAudioError: Error querying device -1`；
2. 改成枚举设备后又踩到 `-9999 UnanticipatedHostError`：PortAudio 在 **WASAPI**
   下不支持 `InputStream.read()`（阻塞读），必须用 callback 模式；
3. 本机麦克风端点实际不可用（枚举得到 `麦克风 (Realtek HD Audio Mic input)`，
   但打开后 1.2 秒一帧音频都没有）。

修复：

- 自己枚举输入设备，**优先真麦克风、排除"立体声混音/loopback"** 这类回环设备；
- 采集改 **callback 模式**（WASAPI 兼容），设备不支持 16k 时自动退到设备默认采样率并线性重采样；
- 三类失败分别给可操作提示：无设备 → 指路系统声音/隐私设置；打开失败 → 报出具体设备名；
  打开成功但无数据 → 明确列出"被独占 / 隐私未授权 / 端点未接入"三种可能；
- 点击前先判 `has_input_device()`，没有设备直接提示并复位按钮（不再进录音线程）；
- 后台线程报错时统一复位麦克风按钮，避免卡在按下态。

附带修排版：`sys/error` 提示条原来按 sizeHint 收缩，长文案被折成一条窄列
（"正在录音…" 占三行）。现在 `_recap` 遍历布局、按字数给最小宽度，短提示紧凑、长提示 1~2 行。

验证：`voice.record_until` 在本机返回精确诊断；回归新增"无麦克风提示与按钮复位"用例，24/24 通过。

## 切换模型后输出变成 0000（用户反馈，同日）

现象：在会话里切到另一个模型后，感觉"还在用刚才的模型"，或者回复一串 `0000…`。

排查过程（全部为实测，不是猜测）：

| 实验 | 结果 |
|------|------|
| `qwen2.5:7b` 回答"1+1" | 正常答 `2` → 机器与 Ollama 本身没坏 |
| `qwen3:4b` 答 BM25 | 正常 → 模型与模板没问题 |
| 切到 `qwen3:8b` 再问 | 返回 `0000…` / `BotBot…` 多语言沙拉 |
| 查内存 | **总 15.7GB，可用 0.5GB（97% 已用）**，两个 `llama-server` 各占 6.2GB / 2.9GB |
| 卸载全部模型后**只加载** `qwen3:8b` | 正常输出（思考 185 字），`think=false` 与 `/no_think` 均能直接给答案 |

结论：**`keep_alive: 10m` 让 Ollama 把用过的每个模型都留在内存里**，
16GB 机器上切两三次（8B 5GB + 4B 2.5GB + KV cache）就把物理内存吃满，
KV cache 分配失败 → 推理退化成重复字符流。这既解释了"0000"，也解释了
"像是还在用上一个模型"（其实是新模型，但吐的是垃圾）。

修复：

1. `_select_model()` → `unload_models_except(new)`：切换时后台调用
   `/api/generate {keep_alive: 0}` 卸载其余模型（实测：加载 4b+1b 后调用，
   `ps` 从 3 个降到 1 个），并提示"已释放上一个模型占用的内存"。
2. `degenerate_output()`：长文本单字符 ≥60% 或全文 ≤3 种字符 → 判定为退化输出，
   **丢弃结果、不写入会话历史**，改为一条可操作提示（换模型/关大程序/查上下文）。
3. 说明书 FAQ 与 README 已知问题同步（原来只归因于 qwen3+4096，已修正为内存优先）。

## 已知限制

- OCR 与向量/语音模型在**轻装版**（`offline_chat_lite.exe`）中不随包，
  相关按钮会自动隐藏或给出"组件不可用"提示，其余功能不受影响。
- `run_python` 沙箱是"纯计算"沙箱：不能读写文件、不能联网；
  需要文件产出时应走 `write_file`（有快照与审计）。
- 定时任务需要 `server/scheduler.py` 常驻（agent 启动时会自动拉起一条后台线程）。
- 深度思考约 3 倍耗时（实测 37-45s / 轮，CPU），仅建议在需要准确度的场合开启。
